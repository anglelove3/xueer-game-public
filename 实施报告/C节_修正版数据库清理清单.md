## 1. 扫描方法与两处自我纠错（重要）

| 口径 | 说明 |
|---|---|
| 指令覆盖 | 111 条件分支 / 122 变量操作 / 126–129 增减 / 301 战斗 / 302·605 商店 / 355·655 脚本 |
| 数据库覆盖 | Map*、CommonEvents、Troops、Actors、Classes、Enemies、Weapons、Armors、Items、Skills、States、System |

| 附加 | `System.partyMembers` / `testBattlers`（含测试装备数组） |

**⚠ 纠错 1（会让结论完全错的那种）**：MZ 事件页条件里 `itemId` / `actorId` **有默认值 1**，但配 `itemValid: false` / `actorValid: false` 表示条件未启用。
第一版扫描器没查标志位，于是报出「物品#1 被引用 319 次」「角色#1 雪儿被引用 374 次」这种荒唐结果。**已改为一律验 `*Valid`。**
连带修正：原《核对报告》里「Map002 事件#9 第 3 页条件含 itemId 101」**也是同一个假阳性**——页 2/3 的条件实际只有独立开关 A/B。

**⚠ 纠错 2**：事件页里的名字在对白中会被**换行拆成两条 401 指令**。
所以做"残留词复查"时**不能只看裸文本**，必须把一页内连续的 401 拼成一个整段再查——批次1 的漏网正是这个原因（见 §3）。
